# 障害対応手順（保守担当者向け）

本書は、`Schedule-System` の保守担当者（技術者）向けに、障害発生時の一次切り分け手順をまとめたものです。  
日々の運用担当者向けの操作手順は `docs/担当者マニュアル.md` を参照してください。

---

## 1. 対象と目的

- 対象: 起動不可 / 検索失敗 / 更新失敗 / 帳票失敗 / 年度追加失敗 / ドキュメント閲覧失敗 / バックアップ終了失敗
- 目的: ログを用いた一次切り分けを5分以内に実施する

---

## 2. まず確認するログ

1. `logs/app.log` を開く
2. エラー時刻の前後で `request_id` を特定する
3. 同一 `request_id` のイベントを追跡する

補足: イベント名や主要フィールドの定義は `docs/ログ出力仕様.md` を参照。

---

## 3. 事象別の確認手順

### 3.1 画面が開けない / 起動しない

1. `app_start` と `navigation_ready` の有無を確認
2. 出ていない場合は `ops/windows/start_app.bat` を実行し再確認
3. それでも不可なら運用管理者へ連絡

### 3.2 検索・更新に失敗する

1. `search_failed` または `update_failed` を確認
2. 同一 `request_id` の直前入力条件（期間、診療科など）を見直す
3. 再実行しても失敗する場合は、画面名・時刻・`request_id` を添えて連絡

### 3.3 帳票出力に失敗する

1. `report_generate_failed` の `report_id` を確認
   - `report1_template` / `report6_template` の場合は、アップロードした `.xlsx` テンプレートのプレースホルダや結合セルも確認
2. 対象期間・対象診療科を再設定して再試行
3. CSV/Excelのダウンロードボタンが出ているのに保存されない場合は、ブラウザのダウンロードブロック・保存先権限を確認
4. 連続2回失敗時は運用管理者へ連絡

### 3.4 年度追加に失敗する

1. `update_failed` の `operation=extend_fiscal_year` を確認
2. マスタ管理画面の「年度管理」で、開始年度・終了年度が逆転していないか確認
3. 既存最大年度の次年度追加なのか、範囲指定追加なのかを確認
4. 同一条件で連続2回失敗する場合は、`M_Date` / `M_Holiday` の対象年度データ有無と `request_id` を添えて連絡

### 3.5 ドキュメント閲覧で文書が表示されない

1. `page_open page=ドキュメント閲覧` が出ているか確認
2. 対象ファイルが次の場所にあるか確認
   - `README.md`
   - `docs/担当者マニュアル.md`
   - `docs/障害対応手順.md`
   - `docs/ログ出力仕様.md`
   - `docs/保守引継ぎ_ページ関連マップ.md`
3. ファイル名を変更した場合は `streamlit_app/page_support.py` の `DOC_FILES` も更新されているか確認

### 3.6 バックアップして終了に失敗する

1. `shutdown_requested` 後に `backup_start` / `backup_success` / `backup_failed` が出ていないか確認
2. `backup_failed reason=non_windows` は、Windowsサーバー以外で押下した場合の想定動作
3. 自動終了しない場合は次を手動実行
   - `ops/windows/backup_db.bat`
   - `ops/windows/stop_app.bat`
4. 翌朝までに `backup_success` / `shutdown_completed` の記録有無を確認

---

## 4. エスカレーション基準

- 同じ操作で連続2回失敗
- 業務開始30分前までに起動不可が解消しない
- バックアップが当日中に取得できない
- 年度追加後に予定検索・反映後予定検索・帳票のいずれかで対象年度が確認できない
- ドキュメント閲覧から主要手順書を参照できず、運用担当者が代替手順を確認できない

連絡時は **発生時刻 / 画面名 / request_id / 実施した手順** を必ず添付する。
