# 担当者用マニュアル（外来スケジュール管理システム）

本マニュアルは、**日次運用の担当者向け**に、起動〜入力〜確認〜帳票出力〜終了までの基本手順をまとめたものです。

---

## 1. 対象者と前提

- 対象者: 外来スケジュールの登録・変更・帳票出力を行う担当者
- 前提:
  - 運用PCに本システム一式が配置されている
  - 初期セットアップ（`python set_up.py`）が完了している
  - ブラウザで `http://localhost:8501` へアクセスできる

---

## 2. 毎日の運用フロー（最短手順）

### 朝（業務開始時）

1. `ops/windows/start_app_silent.vbs` をダブルクリック
   - 状況を確認しながら起動する場合は `start_app.bat`
2. ブラウザで `http://localhost:8501` を開く
   - バッチ起動時は専用ウィンドウが自動で開きます
3. 左メニューから必要な業務ページを選択

### 日中（運用中）

1. 通常枠の修正が必要 → **「枠管理」**
2. 日付単位の変更登録が必要 → **「予定変更入力」**
3. 変更反映後を確認 → **「反映後予定検索」**
4. 変更内容を後から修正/確認したい → **「変更登録履歴検索」**
5. 印刷・共有データ出力 → **帳票①〜⑥**

### 夜（業務終了時）

1. サイドバーの **「💾 バックアップして終了」** を押す（推奨）
   - Windows環境で `backup_db.bat` 実行後に `stop_app.bat` を自動起動
2. うまく終了しない場合は個別実行
   - `ops/windows/backup_db.bat`
   - `ops/windows/stop_app.bat`

---

## 3. 画面別の使い方

### 3.1 枠管理

- 用途: 定常的な診療枠（テンプレート）を登録・修正
- 主な操作:
  - 条件検索
  - 既存枠編集
  - 新規枠追加
- 注意点:
  - 終了日未定は内部的に `9999-12-31` で保持

### 3.2 予定検索

- 用途: 通常枠ベースの予定確認
- 主な操作:
  - 条件検索
  - 対象行選択
  - 選択内容を **予定変更入力** へ連携

### 3.3 予定変更入力

- 用途: 日付単位の変更登録
- タブ構成:
  - 通常枠変更（`T_ScheduleChange`）
  - 臨時外来登録（`T_TemporarySchedule`）
- 注意点:
  - 同一日付・同一枠の変更は最新登録が有効

### 3.4 反映後予定検索

- 用途: 通常枠 + 最新変更 + 臨時外来を統合した最終予定の確認
- 主な使い方:
  - 変更登録直後の確認
  - 帳票出力前の最終チェック

### 3.5 変更登録履歴検索

- 用途:
  - 通常枠変更・臨時外来の履歴検索
  - 登録内容の修正（変更種別、担当医、時間帯、診療科、備考など）
  - `帳票②表示` / `ActiveFlag` の切替
- 出力機能:
  - 一覧CSV出力
  - チェックした対象行のプレビュー
  - **テンプレートExcel反映出力**（プレースホルダ埋め込み）
- テンプレートのプレースホルダ例:
  - `{{列名#行番号}}`（例: `{{診療科#1}}`）
  - `{{列名}}`
  - `{{固定:文字列}}`
- 備考:
  - テンプレート反映版Excelをダウンロードすると、出力履歴が保存されます

### 3.6 帳票1〜6

- 用途: 院内共有・報告用データ出力
- 共通操作:
  - 条件指定 → 画面確認 → CSV/Excel出力
- 補足:
  - 帳票⑥は医師別シートを一括生成

### 3.7 マスタ管理

- 用途: マスタ情報の維持管理
- 管理対象:
  - 診療科、医師、時間帯、専門、帳票診療科、変更種別
- 注意点:
  - マスタ変更は複数画面・帳票に影響するため、変更前後で確認を実施

---

## 4. データ運用ルール（重要）

- 終了日未定は `9999-12-31` として管理
- 帳票振り分けは `Rpt1〜Rpt6` 系カラムで制御
- 予定変更反映は「同一日・同一枠の最新変更」を採用
- 帳票②表示制御は `Rpt2Flag` を使用
- 祝日除外はベースビュー生成時点で適用
- 無効化したデータ（`ActiveFlag=0`）は、履歴画面のチェックで再表示可能

---

## 5. よくある作業パターン

### パターンA: 医師変更（通常枠）

1. 「予定検索」で対象日・対象枠を検索
2. 対象行を選択して「予定変更入力」へ移動
3. 通常枠変更タブで変更内容を登録
4. 「反映後予定検索」で結果確認
5. 必要に応じて帳票②を出力

### パターンB: 臨時外来の追加

1. 「予定変更入力」→ 臨時外来登録タブ
2. 必要項目を入力して登録
3. 「反映後予定検索」で追加結果を確認
4. 必要に応じて帳票①/②を再出力

### パターンC: 登録済み内容の修正

1. 「変更登録履歴検索」で期間検索
2. 編集対象を選択して内容修正
3. 更新後に「反映後予定検索」で最終確認

### パターンD: 変更届の作成

1. 「変更登録履歴検索」で対象期間を検索
2. 絞り込み + 出力対象チェック
3. 出力者・出力日を入力
4. テンプレートExcel（.xlsx）をアップロード
5. 「テンプレート反映版Excelダウンロード」を実行

### パターンE: 業務終了時クローズ

1. サイドバーの「💾 バックアップして終了」を押す
2. エラー時は `backup_db.bat` と `stop_app.bat` を個別実行

## 6. トラブルシュート

### 起動しない

- `start_app.bat` 実行時メッセージを確認
- よくある原因:
  - Python未導入
  - `requirements.txt` の導入失敗（ネットワーク/プロキシ）
  - `streamlit_app/app.py` の配置不備

### 画面は開くが接続できない

- `http://localhost:8501` に直接アクセス
- 8501ポートの競合有無を確認
- `stop_app.bat` 実行後に再起動

### バックアップに失敗する

- `database/schedule.db` の存在確認
- `backups` フォルダの書き込み権限確認

### 変更届テンプレート反映に失敗する

- `.xlsx` 形式か確認（`.xls` は不可）
- プレースホルダの書式を確認（`{{列名#行番号}}` 形式）
- テンプレートのセル結合位置と参照セルの不整合がないか確認

### 終了できない

- `stop_app.bat` を実行
- 解消しない場合はタスクマネージャで 8501ポート利用プロセスを停止

---

## 7. ログの確認

- 実行ログは `logs/app.log`
- ログはローテーション保存（10MB × 10世代）
- 起動/登録/出力/バックアップの問題は直近ログを優先確認
- `logs/` 配下は運用生成物のため Git 管理対象外
