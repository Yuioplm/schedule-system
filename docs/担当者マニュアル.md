# 担当者用マニュアル（外来スケジュール管理システム）

本マニュアルは、**日次運用の担当者向け**に、起動〜入力〜確認〜帳票出力〜終了までの基本手順をまとめたものです。
（2026-04 完全版: 全画面・全機能を同一フォーマットで記載）

---

## はじめに（このアプリで何ができるか）

このアプリは、**外来スケジュールの作成・変更・確認・帳票出力**を一連で行うための運用システムです。
最初に「何をどう操作すると、どの帳票が出るか」の全体像を把握してください。

### できること

診療予定と変更情報を入力することで、**実績管理から帳票出力までを一連で効率的に行えます。**

- 上記を正確に行うために、各種マスタ（診療科・医師・時間帯・変更種別など）を整備する
- 上記を正確に行うために、通常枠（ベースとなる診療枠）を設定・登録する
- 必要に応じて、日々の変更（通常枠変更・臨時外来）を登録する

### 利用開始時の作業イメージ

1. **マスタ管理**で選択肢の元データを整備する
   （診療科、医師、時間帯、変更種別など）
2. **枠管理**で通常枠（曜日・時間帯・担当医）のベースを作る
3. 設定した診療枠と日付マスタをもとに、診療予定一覧（ベース予定）が自動生成される
4. 必要に応じて**予定変更入力**で通常枠変更/臨時外来を登録する
5. **反映後予定検索**で最終予定を確認する
6. 用途に応じて**帳票①〜⑥**を出力する

> つまり、**「マスタ整備 → 枠設定 → ベース予定生成 → 変更入力 → 反映確認 → 帳票出力」** が基本フローです。

### 帳票の種類・内容・主なカラム

| 帳票 | 主な用途 | 主な内容 | 主なカラム例 |
|---|---|---|---|
| 帳票① 外来担当医表 | 院内/外部向け共有 | 曜日別の担当医体制 | 診療科, 時間, 診察室, 月〜土 |
| 帳票② 予定変更一覧 | 変更周知 | 変更登録済み予定の一覧 | 診療日, 診療科, 担当医, 変更種別, 備考 |
| 帳票③ 外来数 | 件数報告 | 対象月の外来数集計 | 年月, 診療科, 区分, 件数 |
| 帳票④ 常勤日別コマ数 | 稼働確認（日次） | 常勤医の1日単位コマ数 | 日付, 医師, AM/PM, コマ数 |
| 帳票⑤ 常勤・非常勤月別コマ数 | 稼働確認（月次） | 勤務形態別の月次コマ数 | 年月, 勤務形態, 合計コマ数 |
| 帳票⑥ 非常勤医師勤務報告 | 医師別報告 | 非常勤医師ごとの勤務状況 | 日, 曜日, AM勤務, PM勤務, 備考 |

※ 実際の出力列は運用テンプレートやSQL更新で増減する場合があります。詳細は各帳票節（3.6〜3.11）を参照してください。

## 1. 対象者と前提

- 対象者: 外来スケジュールの登録・変更・帳票出力を行う担当者
- 前提:
  - 運用PCに本システム一式が配置されている
  - 初期セットアップ（`python set_up.py`）が完了している
  - ブラウザで `http://localhost:8501` へアクセスできる

---

## 2. 毎日の運用フロー

### 朝（業務開始時）

1. `ops/windows/start_app_silent.vbs` をダブルクリック
   - 状況確認しながら起動する場合は `start_app.bat`
2. ブラウザで `http://localhost:8501` を開く
3. 当日作業に合わせて画面を選択（枠管理/予定変更入力/帳票など）

### 日中（運用中）

1. 通常枠の修正 → **枠管理**
2. 日付単位の変更登録 → **予定変更入力**
3. 変更反映確認 → **反映後予定検索**
4. 履歴修正・変更届作成 → **変更登録履歴検索**
5. 共有資料出力 → **帳票①〜⑥**

### 夜（業務終了時）

1. サイドバーの **「💾 バックアップして終了」** を押す（推奨）
2. 自動終了しない場合:
   - `ops/windows/backup_db.bat`
   - `ops/windows/stop_app.bat`

### 3.1 枠管理（`1_枠管理.py`）

#### 目的
通常枠テンプレート（定常運用の基準枠）を登録・編集する。

#### 事前条件
- 診療科/医師/時間帯などのマスタが登録済み
- 変更したい診療期間が確定している

#### 操作手順
1. 条件（診療科、曜日、医師など）を入力して検索
2. 既存枠を編集する場合は対象行を選択
3. 新規追加の場合は入力エリアで必要項目を入力
4. 登録/更新ボタンを押す
5. 必要に応じて「予定検索」で表示確認

#### 期待結果
- 登録した枠が一覧に反映される
- 有効期間（開始日/終了日）が正しく保存される

#### よくあるエラーと対処
- 医師が選択できない: `M_Doctor` マスタを確認
- 想定日で表示されない: `WeekPattern` と有効期間を確認

#### 関連ページ

- 後: 予定検索 / 予定変更入力

### 3.2 予定検索（`2_予定検索.py`）

#### 目的
通常枠ベースの予定を確認し、変更対象を特定する。

#### 事前条件
- 枠管理に対象枠が存在する
- 対象期間が決まっている

#### 操作手順
1. 検索条件（期間、診療科、医師など）を設定
   - 開始日を変更すると、終了日は開始日と同日に自動同期されます（必要があれば終了日を再指定）
2. 検索実行
3. 対象行を選択
4. 必要に応じて「予定変更入力」へ遷移

#### 期待結果
- 条件に一致する予定が一覧表示される
- 選択した行情報が変更入力画面へ連携される

#### よくあるエラーと対処
- 結果0件: 期間/曜日条件を緩める
- 開始日変更後に想定より検索範囲が狭い: 自動同期された終了日を再確認し、必要な終了日へ再設定する
- 連携できない: セッション情報の再読み込み（画面再表示）

### 3.3 予定変更入力（`3_予定変更入力.py`）

#### 目的
日付単位で通常枠変更または臨時外来を登録する。

#### 事前条件
- 変更対象日と対象枠が確定している
- 必要マスタ（医師・時間帯・診療科）が存在する

#### 操作手順
1. 「通常枠変更」または「臨時外来登録」タブを選択
2. 通常枠変更では「変更種別」を先に選択する
   - 「代診」選択時のみ、代診医検索（部署・勤務形態）と代診医選択が有効になります
   - 「代診」以外では代診医入力は無効で、変更後医師は未設定として登録されます
3. 必須項目を入力（診療日、時間帯、診療科、変更内容）
4. 必要に応じて備考・表示フラグ（`Rpt2Flag`）を設定
   - 変更者は任意入力です（未入力時は `NULL` 保存）
5. 登録ボタンを押す
6. 「反映後予定検索」で反映確認

#### 期待結果
- 登録完了メッセージが表示される
- 対象日の最終予定に変更が反映される

#### よくあるエラーと対処
- 重複入力: 同一日・同一枠の最新登録を再確認
- 代診医が選択できない: 変更種別が「代診」になっているか確認（代診以外は入力無効）
- 取消を反映できない: 変更種別マスタを確認

#### 関連ページ
- 前: 予定検索
- 後: 反映後予定検索 / 帳票②

#### 関連SQL / テーブル
- `T_ScheduleChange`, `T_TemporarySchedule`, `M_ScheduleChangeType`

### 3.5 変更登録履歴検索（`5_変更登録履歴.py`）

#### 目的
登録済み変更の検索・修正・帳票②表示制御・テンプレートExcel出力を行う。

#### 事前条件
- 対象期間に `T_ScheduleChange` または `T_TemporarySchedule` の登録がある
- 変更届テンプレート（`.xlsx`）を準備済み

#### 操作手順
1. 期間・診療科などで検索
2. 対象行を編集（変更種別、担当医、時間帯、備考等）
3. 必要に応じて `Rpt2Flag` / `ActiveFlag` を切替
4. 一覧CSVまたはチェック行プレビューを確認
5. テンプレートExcelをアップロードして反映出力

#### 期待結果
- 編集内容が保存される
- テンプレート反映版Excelがダウンロードできる
- 出力履歴が保存される

#### よくあるエラーと対処
- テンプレート反映失敗: プレースホルダ記法（`{{列名#行番号}}` 等）を確認
- 編集後に見えない: `ActiveFlag` 条件を確認

### 3.6 帳票① 外来担当医表（`6_帳票1.py`）

#### 目的
外来担当医表を作成し、院内共有用に出力する。

#### 事前条件
- 対象期間の最終予定が確定している
- 院内用/外部用のどちらで配布するか決まっている
- テンプレート反映版を使う場合は `.xlsx` テンプレートを準備している

#### 操作手順
1. 年・月を指定し、小カテゴリ（院内用/外部用）を選択
2. 画面表示形式（改行表示/区切り表示）を選んでプレビュー確認
3. 必要に応じて「Excelダウンロード（CSV）」を実行
4. テンプレート利用時は `.xlsx` をアップロードし、プレースホルダ反映版を出力

#### 期待結果
- 部門別・外部向けを含め正しい表が出力される
- 院内用/外部用で表示ルール（氏名・週表記）が切り替わる
- テンプレート反映版でも罫線・レイアウトが維持される

#### よくあるエラーと対処
- 対象データがない: 対象年月とマスタ有効期間、変更反映状況を確認
- テンプレート反映が空欄になる: プレースホルダ形式（`{{年}}`, `{{月|診療科|時間|診察室}}` など）を確認
- 想定セルに書き込まれない: 結合セル時は先頭セルにプレースホルダを配置

## 4. データ運用ルール

### 4.1 診療科名の使い分けルール

日次運用で混乱しやすいポイントのため、先に結論を明記します。

- マスタ管理画面の「診療科」タブ（`M_ClinicalDepartment`）では、診療科ごとの**帳票出力対象（Rpt1Flag〜Rpt6Flag）**を設定します。
- 同じくマスタ管理画面の「診療科」タブ（`M_ClinicalDepartment`）の `Rpt1Sort` で、**帳票①の表示順**を設定します。
- 枠管理画面（`T_ConsultationSlot`）では、枠ごとに
  - `Rpt1ClinDeptID`（帳票①用の基準診療科）
  - `Rpt2ClinDeptID`〜`Rpt6ClinDeptID`（帳票②〜⑥向け診療科）
  を設定します。
- 帳票②〜⑥で表示する診療科・専門外来名・医師名の使い分けは、マスタ管理画面の「帳票診療科名」タブ（`M_ReportClinicalDepartment`）の参照設定で制御します。

#### 4.1.1 4つのベース画面での診療科名の意味

以下の画面でベースとして使う「診療科名」は、枠管理画面（`T_ConsultationSlot`）で設定する **`Rpt1ClinDeptID`（帳票①用診療科名）** です。

- 予定検索（`2_予定検索.py`）
- 予定変更入力（`3_予定変更入力.py`）
- 反映後予定検索（`4_反映後予定検索.py`）
- 変更登録履歴検索（`5_変更登録履歴.py`）

> 画面上の「診療科名」を変更したい場合、まず枠管理画面（`T_ConsultationSlot`）の `Rpt1ClinDeptID` 設定を確認してください。
> 帳票②〜⑥のみの名称変更であれば、枠管理画面（`T_ConsultationSlot`）の `Rpt2ClinDeptID`〜`Rpt6ClinDeptID` と、マスタ管理画面の「帳票診療科名」タブ（`M_ReportClinicalDepartment`）を見直します。

### 4.2 予定変更・帳票反映ルール

- 通常枠変更は「同一日・同一枠の最新変更（最新 `ChangeID`）」が採用されます。
- 帳票②に出ない場合は、マスタ管理画面の「診療科」タブ（`M_ClinicalDepartment`）で `Rpt2Flag` と `ActiveFlag` を合わせて確認してください。加えて、予定変更入力画面で設定した通常枠変更の「帳票②に表示しない（`hide_from_report2`）」および臨時外来登録の「帳票②に表示しない（`temp_hide_from_report2`）」が `T_ScheduleChange.Rpt2Flag` / `T_TemporarySchedule.Rpt2Flag` に反映されていないか確認してください。
- 無効化（`ActiveFlag=0`）したデータは、マスタ管理画面や変更登録履歴検索画面で再確認・再有効化できます。

### 4.3 期間・日付・祝日ルール

- 終了日未定は `9999-12-31` で管理します。
- 祝日除外はベースビュー（通常枠展開）生成時点で適用されます。
- 年度追加後は、対象期間の表示・帳票結果を必ず「予定検索 / 反映後予定検索 / 帳票」で確認してください。

### 4.4 取消・臨時外来の扱い

- 取消（`ChangeTypeID=1`）で登録した変更は、反映後予定（`V_ScheduleActual`）では表示対象から除外されます。
- 臨時外来は予定変更入力画面の「臨時外来」タブ（`T_TemporarySchedule`）で通常枠とは別管理され、反映後予定上は `SlotID` が `NULL` の行として扱われます。
- 臨時外来を帳票②へ出す場合も、マスタ管理画面の「診療科」タブ（`M_ClinicalDepartment`）で `Rpt2Flag=1` かつ `ActiveFlag=1` を確認してください。あわせて、臨時外来登録時の `temp_hide_from_report2` がOFF（= `T_TemporarySchedule.Rpt2Flag=1`）になっていることを確認してください。

### 4.5 マスタ整合性チェック（登録前後）

- 枠管理画面（`T_ConsultationSlot`）の `Rpt1ClinDeptID` は、マスタ管理画面の「診療科」タブ（`M_ClinicalDepartment`）との整合性を確認してください。
- 同じく枠管理画面（`T_ConsultationSlot`）の `Rpt2`〜`Rpt6ClinDeptID` は、マスタ管理画面の「帳票診療科名」タブ（`M_ReportClinicalDepartment`）との整合性を確認してください。
- 予定が出ない場合は、診療科だけでなくマスタ管理画面の「医師」「時間帯」タブ（`M_Doctor`, `M_TimeSlot`）の `ActiveFlag` と参照ID整合性も確認してください。

## 6. トラブルシュート

### 起動しない
- `start_app.bat` のメッセージ確認
- Python未導入 / 依存未導入 / ファイル配置ミスを確認

### 画面は開くが接続できない
- `http://localhost:8501` に直接アクセス
- ポート競合を確認
- `stop_app.bat` 後に再起動

### バックアップに失敗する
- `database/schedule.db` の存在確認
- `backups` への書込権限確認

### 変更届テンプレート反映に失敗する
- `.xlsx` 形式確認
- プレースホルダ構文確認
- 結合セルの参照不整合確認
