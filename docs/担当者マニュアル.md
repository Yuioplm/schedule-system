# 担当者用マニュアル（外来スケジュール管理システム）

本マニュアルは、**日次運用の担当者向け**に、起動〜入力〜確認〜帳票出力〜終了までの基本手順をまとめたものです。
（2026-04 完全版: 全画面・全機能を同一フォーマットで記載）

---

## 0. マニュアル運用標準（スクリーンショット付き運用手順）

### 0.1 章立てテンプレート（各画面で共通）

各画面は必ず次の順で記載します。

1. **画面の目的（何のための画面か）**
2. **事前条件（必要なマスタ、前画面、期間条件など）**
3. **操作手順（1操作=1ステップ）**
4. **期待結果（完了判定）**
5. **よくあるエラーと対処**
6. **関連ページ（前後導線）**
7. **関連SQL / テーブル（保守担当向け）**

### 0.2 スクリーンショット運用ルール（推奨）

- 保存場所: `docs/images/manual/`
- ファイル名規則: `<ページ番号>_<ページ名>_<連番>_<状態>.png`
  - 例: `03_予定変更入力_01_初期表示.png`
- 1画面あたり最低3枚:
  1. 初期表示
  2. 入力中
  3. 登録/出力後
- マスキング必須:
  - 個人名（患者情報含む）
  - 共有不可の院内コード
- 各画像の直下に必ず記載:
  - この画像で行う操作
  - 成功時に確認すべきポイント

### 0.3 記載サンプル（予定変更入力）

#### 目的

通常枠の変更または臨時外来の追加を日付単位で登録する。

#### 操作手順（例）

1. サイドバーで「予定変更入力」を開く
2. 「通常枠変更」または「臨時外来登録」タブを選択
3. 必須項目（診療日、診療科、医師、時間帯など）を入力
4. 「登録」ボタンを押す
5. 「反映後予定検索」で結果を確認する

#### 確認ポイント

- 登録完了メッセージが表示される
- 反映後予定検索で対象データが表示される
- 帳票②に載せる場合は `Rpt2Flag` を確認

## 1. 対象者と前提

- 対象者: 外来スケジュールの登録・変更・帳票出力を行う担当者
- 前提:
  - 運用PCに本システム一式が配置されている
  - 初期セットアップ（`python set_up.py`）が完了している
  - ブラウザで `http://localhost:8501` へアクセスできる

---

## 2. 毎日の運用フロー（最短手順）

### 朝（業務開始時）

1. `ops/windows/start_app_silent.vbs` をダブルクリック
   - 状況確認しながら起動する場合は `start_app.bat`
2. ブラウザで `http://localhost:8501` を開く
3. 当日作業に合わせて画面を選択（枠管理/予定変更入力/帳票など）

### 日中（運用中）

1. 通常枠の修正 → **枠管理**
2. 日付単位の変更登録 → **予定変更入力**
3. 変更反映確認 → **反映後予定検索**
4. 履歴修正・変更届作成 → **変更登録履歴検索**
5. 共有資料出力 → **帳票①〜⑥**

### 夜（業務終了時）

1. サイドバーの **「💾 バックアップして終了」** を押す（推奨）
2. 自動終了しない場合:
   - `ops/windows/backup_db.bat`
   - `ops/windows/stop_app.bat`

### 3.1 枠管理（`1_枠管理.py`）

#### 目的
通常枠テンプレート（定常運用の基準枠）を登録・編集する。

#### 事前条件
- 診療科/医師/時間帯などのマスタが登録済み
- 変更したい診療期間が確定している

#### 操作手順
1. 条件（診療科、曜日、医師など）を入力して検索
2. 既存枠を編集する場合は対象行を選択
3. 新規追加の場合は入力エリアで必要項目を入力
4. 登録/更新ボタンを押す
5. 必要に応じて「予定検索」で表示確認

#### 期待結果
- 登録した枠が一覧に反映される
- 有効期間（開始日/終了日）が正しく保存される

#### よくあるエラーと対処
- 医師が選択できない: `M_Doctor` マスタを確認
- 想定日で表示されない: `WeekPattern` と有効期間を確認

#### 関連ページ
- 前: マスタ管理
- 後: 予定検索 / 予定変更入力

#### 関連SQL / テーブル
- `T_ConsultationSlot`, `M_ClinicalDepartment`, `M_Doctor`, `M_TimeSlot`

### 3.3 予定変更入力（`3_予定変更入力.py`）

#### 目的
日付単位で通常枠変更または臨時外来を登録する。

#### 事前条件
- 変更対象日と対象枠が確定している
- 必要マスタ（医師・時間帯・診療科）が存在する

#### 操作手順
1. 「通常枠変更」または「臨時外来登録」タブを選択
2. 必須項目を入力（診療日、医師、時間帯、診療科、変更内容）

- 登録完了メッセージが表示される
- 対象日の最終予定に変更が反映される

#### よくあるエラーと対処
- 重複入力: 同一日・同一枠の最新登録を再確認
- 取消を反映できない: 変更種別マスタを確認

#### 関連ページ

- 後: 反映後予定検索 / 帳票②

### 3.5 変更登録履歴検索（`5_変更登録履歴.py`）

#### 目的
登録済み変更の検索・修正・帳票②表示制御・テンプレートExcel出力を行う。

#### 事前条件
- 対象期間に `T_ScheduleChange` または `T_TemporarySchedule` の登録がある
- 変更届テンプレート（`.xlsx`）を準備済み

#### 操作手順
1. 期間・診療科などで検索
2. 対象行を編集（変更種別、担当医、時間帯、備考等）
3. 必要に応じて `Rpt2Flag` / `ActiveFlag` を切替
4. 一覧CSVまたはチェック行プレビューを確認
5. テンプレートExcelをアップロードして反映出力

#### 期待結果
- 編集内容が保存される
- テンプレート反映版Excelがダウンロードできる
- 出力履歴が保存される

#### よくあるエラーと対処
- テンプレート反映失敗: プレースホルダ記法（`{{列名#行番号}}` 等）を確認
- 編集後に見えない: `ActiveFlag` 条件を確認

## 4. データ運用ルール（重要）

- 終了日未定は `9999-12-31` として管理
- 帳票振り分けは `Rpt1〜Rpt6` 系カラムで制御
- 予定変更反映は「同一日・同一枠の最新変更」を採用
- 帳票②表示制御は `Rpt2Flag` を使用
- 祝日除外はベースビュー生成時点で適用
- 無効化データ（`ActiveFlag=0`）は履歴検索で再確認可能

## 5. よくある作業パターン

### パターンA: 医師変更（通常枠）
1. 「予定検索」で対象行を検索
2. 「予定変更入力」で通常枠変更を登録
3. 「反映後予定検索」で確認
4. 必要時、帳票②を再出力

### パターンB: 臨時外来追加
1. 「予定変更入力」臨時外来タブで登録
2. 「反映後予定検索」で確認
3. 帳票①/②を必要に応じ更新

### パターンC: 登録済み変更の修正
1. 「変更登録履歴検索」で対象を検索
2. 編集して保存
3. 最終確認（反映後予定検索）

### パターンD: 変更届の作成
1. 履歴検索で対象抽出
2. チェック対象選択
3. テンプレートExcelを反映出力

### パターンE: 業務終了
1. 「💾 バックアップして終了」
2. 失敗時は `backup_db.bat` → `stop_app.bat`

## 6. トラブルシュート

### 起動しない
- `start_app.bat` のメッセージ確認
- Python未導入 / 依存未導入 / ファイル配置ミスを確認

### 画面は開くが接続できない
- `http://localhost:8501` に直接アクセス
- ポート競合を確認
- `stop_app.bat` 後に再起動

### バックアップに失敗する
- `database/schedule.db` の存在確認
- `backups` への書込権限確認

### 変更届テンプレート反映に失敗する
- `.xlsx` 形式確認
- プレースホルダ構文確認
- 結合セルの参照不整合確認
